fix: out-of-route floors no longer crash the resync (layer1 vs patrol range [layer2..]); per-frame detection stays authoritative

Observed crash (every frame):
  File "...\movement_worker.py", line 2923, in _resync_route_layer
    detected_index = self._route_layers.index(detected_name)
  ValueError: 'layer1' is not in list

The per-frame world override correctly reads layer1 (the character
starts/fell on layer1 while the patrol range begins at layer2), but the
resync then indexed that name into the patrol-route list - layer1 is NOT
in it, so every frame crashed before any key was sent ("movement
analysis failed; no key sent" spam at 16:03).

- _resync_route_layer: a detected floor OUTSIDE the patrol route now
  returns None instead of indexing it.  Start-on-layer1 / fall-to-layer1
  therefore leaves the patrol state untouched, and the existing
  out-of-range return logic (climb back using layer1's own rope) re-enters
  layer2 before patrol starts - the expected flow (start on layer1 ->
  return to layer2 -> patrol).
- Per-frame world-nearest detection is unchanged and still runs every
  frame; only the route indexing is guarded.
- test: resync on layer1 (patrol not started, and during a layer2 patrol)
  -> None, no crash, active layer index untouched.
