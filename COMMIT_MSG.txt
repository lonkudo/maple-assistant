fix: character position becomes a per-frame dispatch worker + stale-climb brake + return.climb stall recovery

The 16:27 log shows the freeze mechanism clearly: the character is on
layer1 doing "MOVE TO ROPE | pos=(0.335106, 0.567708) ... action=right"
every frame but NEVER moves - no keys are sent and no suppression warning
fires, while the attack worker reports "jump-climb input is active" every
frame.  The climb state machine got stuck with Up-hold active from an
earlier failed grab attempt; that stale climb input silently swallowed
every left/right floor walk (the direction key is gated while climb input
is active), freezing the character on layer1 forever.  The dispatcher
architecture also means the marker is now detected on EVERY frame
independently of the movement loop, so a freeze can never hide the real
position.

- NEW character_worker.py: CharacterWorker(thread) detects the yellow
  player diamond on every dispatched frame (never gated by focus /
  movement state) and publishes CharacterPosition(x, y, confidence) to a
  positions queue.  minimap region comes from a provider (the movement
  worker's latest stabilised region) so both workers crop the same box.
- movement_worker: new optional character_positions queue - when wired,
  the dispatched position overrides the worker's own per-frame marker read
  (per-frame layer detection continues via the same observation chain).
- movement_worker floor-walk branch: stale-climb brake - if the decision
  is a plain left/right floor walk while the climb state still reports
  Up held (stuck from a failed grab + focus dip that released the OS key
  but not the state machine) and the marker Y still sits inside the
  current route layer's band (on the floor, not on the rope arc), release
  Up and reset the climb state before walking.
- movement_worker rope-walk branch: the existing rope-approach stall
  recovery now ALSO covers the return climb (route label "return.climb",
  which is not ".rope") - a bench/fence mid-return otherwise freezes the
  return-to-route walk forever.
- assistant.py: character_frames added to the frame-bus subscribers;
  CharacterWorker created (wired to movement_worker._last_minimap_region)
